# GDM-003 custom-feature follow-up — 2026-11-18

The earlier pause decision used comparison scripts tailored to the first fixture. This follow-up adds a different, owned Godot 4.7.2 export with an explicit `premium` custom export feature and a more-specific `windows.release.x86_64.premium` GDExtension library entry. The export returned 0, staged `premium.dll` rather than the generic `extension.dll`, and the owned game reported the extension loaded. A copy with `premium.dll` removed returned 0 from the game process but reported the extension not loaded and its library missing. The editor continued to report the previously recorded root-certificate-store error in this environment.

The original spike rejected the unfamiliar tag as incomplete, rather than guessing. The fixture experiment was extended to accept explicitly supplied active custom features. With `--feature premium`, it selected the exact tagged entry, reported no fixture finding for the clean package with exit 3 because other checks remain unknown, and reported the missing root file for the negative package with exit 1. Without the explicit feature, it still rejects the unfamiliar tag. This is not automatic export-preset inference or general support for arbitrary Godot metadata, PCKs, custom tags or versions.

A separate small DIY feature-selection helper, given the same explicit tag, selected the same entry and returned 0 for the clean package and 1 for the missing package. Without the tag it returned incomplete. One warm command run took 98/105 ms for the helper and 827/147 ms for the integrated spike on the clean/missing cases respectively; these are non-equivalent, single executions, exclude setup and human work, and are not a product performance comparison. The helper only selects a fixture entry and checks its root filename; the spike also performs its bounded PE/fixture analysis. Neither output proves runtime compatibility.

The owned fixture builder and tests were extended with this case. A fresh rebuild reproduced both the successful clean run and failed missing-file run; eight PE tests, twenty fixture integration tests and two custom-feature helper tests passed against the rebuilt files. This broadens the actual evidence but does not prove general equivalence of the free workflow or a material product advantage. The feasibility decision remains conditional; the operator already knew the fixture, so independent diagnosis time and customer value remain unmeasured. No spending, outreach, publication, customer contact or sale occurred.
