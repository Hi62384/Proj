# GDM-002 movement callback experiment — 2026-11-18

The local proof now includes `callback_fixture.gd`, which uses the earlier FIFO ledger for a single vehicle, and `fixture_mover.gd`, a minimal 3D node controller that emits a callback after reaching a target. In Godot 4.5.1 stable official, the four headless scripts `test_transit.gd`, `test_scheduled.gd`, `test_callback.gd` and `test_movement.gd` all exited 0. The movement test moved two nodes at different speeds, verified boarding only upon arrival, canceled one reservation mid-movement and verified its late callback did not board the passenger. The callback test checked FIFO allocation, duplicate boarding rejection, cancellation, reallocation and seat release. The engine emitted its root certificate store warning on each run.

This is a separate single-vehicle experiment, not an integrated scheduled two-vehicle journey. The test invokes a deterministic `advance` method; it does not use NavigationAgent, collision, a real game controller or an inspected 3D display. A canceled mover continues to its original target; recovery behavior is not implemented. The coordinator has no snapshot, transfer, timeout, disruption or general routing support. No comparison against the native navigation or FlowAI baselines has been run and no integration-time advantage or commercial demand is established. The schedule fixture remains independent of the ledger.

Next: connect callback-driven boarding and disembarking to the scheduled transfer scenario and test save/load across boarding, then evaluate equivalent traces and integration effort against native NavigationLink and FlowAI. No external commercial action or spending occurred.

A separate ledger-backed fixed two-leg schedule (`callback_schedule.gd`) now opens boarding explicitly and accepts controller acknowledgments. `test_callback_schedule.gd` passed headlessly on Godot 4.5.1 (80 events): its instantaneous acknowledgments produce the same event trace as the original synthetic schedule, and a trusted Variant disk save made after one boarding acknowledgement resumes identically. The test also checks a duplicate acknowledgement after restore, a callback outside the departure window and cross-vehicle duplicate ownership rejection. A missing acknowledgement retains a reservation until the next departure; timeout, cancellation, unique callback tokens, stale callbacks coinciding with a later departure and physical recovery remain unimplemented. The 3D mover is not yet wired to this schedule; this is not a full 3D transfer demonstration.

The portfolio browser build and `--check` and commercial checks passed. The full portfolio suite passed on rerun (94 tests, one skipped). No same-scenario native or FlowAI evaluation has been performed; the prior network restriction still affects fetching FlowAI.

Later on 2026-11-18, the fixed callback schedule was extended with per-passenger boarding-window tokens and version 2 snapshots. The previous token is rejected when a later departure opens, and a fresh token is accepted; the disk save/replay test still passes. Version 1 callback-schedule snapshots are now rejected; no migration is implemented. A test connects 20 simple Node3D movers to the schedule and checks that each boards only when its simulated movement reaches its target; it completes 80 trace events. The test resets each mover at each leg and does not animate vehicle travel, handle collision, or inspect the view. It does not test snapshotting the mover itself. Missing callbacks still retain reservations until a later departure and physical recovery is not implemented.

A separate Godot NavigationServer3D test constructed two disjoint navigation regions and a link. Its path reached the destination when enabled and did not when disabled. This is a primitive check, not a same-trace baseline or measurement of queue, transfer, save/load or integration effort. Seven proof scripts passed on Godot 4.5.1 with exit 0; all emitted a root certificate store warning. The native primitive initially failed while the asynchronous navigation map had not synchronized; the test now waits 60 physics frames before each query, which passed in this run but may require adjustment on slower systems. FlowAI remains untested.

A subsequent change closes missed boarding windows by releasing unacknowledged reservations and returning passengers to the front of the FIFO queue. The callback schedule test passed with checks for preserved order, rejection of the old token at the next departure and acceptance of the new token. Physical repositioning is still not implemented. These are fixed-fixture behaviors, not a tested general disruption or rerouting system.

On a later run, the simple projection was rendered on the local NVIDIA OpenGL renderer and inspected at tick 0 and tick 6. The camera framing was enlarged and a label added; the second frame showed tick 6 and two completed passengers. This view still depicts the earlier automatic schedule, not the callback-ledger schedule, and the vehicles jump between projected positions; it is not an end-to-end movement demo. The capture script is `capture_fixture.gd` and the images were retained in the ignored local test directory.

A small demonstration adapter now commands a partially moved passenger back to its original waiting point after a missed departure. `test_recovery.gd` passed on Godot 4.5.1: it checks partial movement, explicit recovery, return to the starting point and boarding at the next departure. The calling controller must invoke recovery; collisions, navigation, mid-motion save/load and disruption rerouting are not covered.

The new `ledger_view.tscn` connects the ledger-backed schedule, moving Node3D markers and recovery adapter. A headless simulation advanced 1,500 fixed steps, reporting 20 completed passengers and one intentionally missed departure. A rendered 1152×648 OpenGL frame was inspected at tick 2; it displayed one miss and the two services. Vehicle interpolation and queue placements are demonstration logic, not navigation or collision physics; mover positions are not included in the schedule snapshot and a full visual save/load replay has not been tested.

A separately written minimal FIFO timetable was combined with a three-stop native NavigationLink path check. It reproduced the same 80-event happy-path trace and a trusted disk-save continuation. The same FIFO timetable was then paired with a FlowAI three-node graph at commit `f0fca85e3222cc2ad42d9668eb22006b149e1d71`, with the same result; FlowAI emitted its prior shutdown resource warnings. Neither baseline drives actual NPC navigation during the timetable or implements delayed callbacks, cancellation, missed-boarding recovery or equivalent disruption tests. Integration time was not measured. The happy path therefore demonstrates that a short custom queue can reproduce that limited case, but it neither establishes nor disproves an advantage for the full intended lifecycle. See `research/README.md` for reproduction.

The ledger-backed visual scene now provides a separate trusted local demo snapshot containing schedule state, demo phase, mover position/target/speed/command and recovery-adapter state. `test_visual_save.gd` saved during the first boarding movement, restored a second scene from disk, compared snapshots and then compared the complete continuation through all 20 arrivals. It also rejected one negative-speed actor snapshot without changing the current scene. This is a fixed-demo replay test, not a hardened untrusted save format or proof for arbitrary controllers, navigation or all transitions. The fixed callback schedule also now accepts cancellation while queued or boarding. Its test verifies a canceled reservation rejects the old callback, duplicate cancellation is rejected, canceled state can be restored, and the other passengers retain queue order. It does not cancel an onboard passenger or automatically move a canceled actor to safety. The affected schedule, recovery, visual simulation and visual save/replay tests passed after this addition.
