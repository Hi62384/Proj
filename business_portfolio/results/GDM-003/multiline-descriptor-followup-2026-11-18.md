# GDM-003 multiline descriptor follow-up — 2026-11-18

Godot's [GDExtension descriptor documentation](https://docs.godotengine.org/en/stable/engine_details/engine_api/gdextension/gdextension_file.html) describes dictionary-valued dependency entries. An owned Godot 4.7.2 project used relative `./bin/` paths and a dependency dictionary split across lines with a trailing comma. Editor import and release export returned zero. The clean exported game reported that the extension loaded; a copy with `leaf.dll` removed reported load failure and Windows error 126, while the game process still returned zero. These observations concern the controlled fixture, not every Godot descriptor or host.

Initially the integrated spike and the separate fixture-specific Dependencies helper both rejected the valid multiline map. The spike now parses a bounded JSON-style subset with multiline dictionaries, trailing commas and semicolon comments, rejecting duplicate keys and sections and malformed or oversized inputs. This remains a trusted-fixture experiment, not a general Godot parser or safe scanner for untrusted input. The independently implemented helper now accepts this simple multiline map and trailing comma, but rejects semicolons and nested braces. Both remain restricted in supported paths and feature selection; the separate collision helper still rejects multiline maps rather than interpreting them.

Dependencies 1.11.1 `-json -chain -depth 4` on the missing-leaf export, followed by the updated independent helper, identified `extension.dll → root.dll → middle.dll → leaf.dll` and its declared empty destination; the helper returned 1. The integrated spike also identified the missing leaf and its relative declaration. Source and package hashes were unchanged in the tested clean scan. A fresh source-driven fixture matrix rebuilt successfully, with the cyclic variant data-only. Eight PE tests, 23 integration tests (one optional handle-mode test skipped), four DIY-helper tests, two descriptor-subset tests, two builder tests, three custom-feature tests, two collision-helper tests and two symbol-helper tests passed. An initial invocation of two standalone helper suites mistakenly passed an extra positional argument; both passed when rerun with their documented invocation.

This case exposes and corrects limitations in both controlled workflows; it does not establish a material commercial advantage, general equivalence, customer demand, or safe hostile-input handling. The conditional feasibility pause and CAD0 authorization remain. No spending, outreach, publication, or sale occurred.

The integration suite was subsequently rerun against the same fresh matrix with the optional experimental handle probe supplied: all 23 tests passed without skips. Its handle-mode comparison covers the existing selected fixture cases; it does not establish race-safe metadata traversal or hostile-input safety, and does not alter the feasibility decision.
