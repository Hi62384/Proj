# GDM-003 relative descriptor path follow-up — 2026-11-18

Godot's [GDExtension descriptor documentation](https://docs.godotengine.org/en/stable/engine_details/engine_api/gdextension/gdextension_file.html) describes relative library paths. A new owned Godot 4.7.2 fixture replaced the original `res://addons/fixture/bin/...` library and dependency paths with `./bin/...` paths. Export returned 0 and staged the owned DLLs beside the executable; the game reported the extension loaded. In a package copy with `leaf.dll` removed, the game reported error 126 and the extension did not load, while the process still returned 0. These observations are confined to this fixture and host.

The original fixture spike returned incomplete for the relative library path. Dependencies found the missing static import chain, but the original DIY helper incorrectly reported `leaf.dll` absent from the descriptor because it only extracted `res://` paths. That was an erroneous explanation, not a valid comparison result. Both experiments were corrected for the two explicitly supported fixture forms. The spike now retains the original `./bin/extension.dll` declaration, records its fixture-specific normalized `res://` form, and reports the missing chain with the actual `./bin/leaf.dll` declaration. The corrected Dependencies helper reports that the leaf is declared with an empty destination. Tests also reject an unsupported `../` dependency path rather than claiming it is absent.

The source-driven builder was extended and run in a fresh directory; the clean and missing-leaf runs reproduced. Against that rebuilt matrix, eight PE tests, twenty-one integration tests, two Dependencies-helper tests and three feature-helper tests passed. This is deliberately limited to simple `./bin/<file>` and `res://addons/fixture/bin/<file>` forms in the selected fixture descriptor. It does not establish general path resolution, PCK handling, arbitrary relative paths, other descriptors' relative paths, or hostile-input safety. The small feature-selection helper was also extended to recognize the same two fixture library forms. This follow-up exposes a concrete error in the earlier free comparison, but the corrected small helper can explain the tested case; general parity, material product advantage, authoring time and demand remain unproven. No spending, outreach, publication, customer contact or sale occurred.
