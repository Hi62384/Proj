# GDM-002 scheduled fixture checkpoint — 2026-11-18

The original local proof in `products/game-tools/gdm-002-transit-proof/` now includes a fixed, experimental integer-tick schedule: 20 synthetic passengers, two vehicles (capacities three and two), one transfer, FIFO tickets and one-tick outbound trips. Arrivals are processed before departures at the same tick. This is a fixed scenario, not a general route planner, addon or controller integration. The earlier independent seat ledger is not yet wired into this fixture.

Using Godot 4.5.1 stable official Windows x64 (`f62fdbde1`) with `APPDATA` redirected to a writable test directory, `--headless --path products/game-tools/gdm-002-transit-proof --script res://test_scheduled.gd` exited 0 and printed `Scheduled fixture: PASS (0 failures; 80 events)`. It saves a Godot Variant snapshot to disk at tick 3, restores it, and compares the complete remaining state and event trace after 100 further ticks. The checks cover capacity, completion of all passengers, and rejection of one invalid occupancy snapshot. The engine emitted a root certificate store warning. The first attempt without writable user data crashed while creating its log directory; redirecting `APPDATA` resolved that environmental problem. Variant data is suitable here only as a trusted local fixture; no untrusted save-file safety claim is made.

`fixture_view.tscn` is an original 3D projection of the fixture with simple primitive markers. A headless startup for 10 frames exited 0 without script errors after correcting an initial parse error. It has not been visually inspected, tested for readable motion, integrated with navigation, or run through a full journey in the GUI. It should not be presented as a finished demo.

[Godot NavigationLinks](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationlinks.html) connect navigation polygons but document that specialized traversal requires game code. [FlowAI](https://github.com/a6xdev/FlowAI) describes a Godot pathnode navigation plugin with moving areas. These descriptions do not measure the same scenario or establish relative implementation effort. Neither baseline has been run on this fixture, and no measured advantage or customer demand is established.
