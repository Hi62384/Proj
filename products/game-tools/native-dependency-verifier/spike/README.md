# Local feasibility spike

This is an experiment for the owned fixture, not a general tool or a release. `PeProbe` inspects one PE's machine and ordinary and RVA-form delay-import names; `fixture_spike.py` combines it with a restricted JSON-style descriptor subset, including multiline dictionaries, trailing commas and semicolon comments, a fixed Windows x64 release feature set and the flat export layout observed in the controlled Godot 4.7.2 fixture. In the selected fixture descriptor it recognizes simple `res://addons/fixture/bin/<file>` and `./bin/<file>` paths; arbitrary relative paths and other descriptors' relative paths remain unsupported. Active custom tags can be supplied explicitly with `--feature <tag>`; it does not infer them from the export preset and refuses unrecognized tags. It distinguishes the most-specific library selection from the first-matching dependency-map selection for the supplied feature set, compares selected staging declarations, and reports a byte difference between a uniquely declared fixture source and a root-staged file. A byte difference alone does not prove a defect: signing or other legitimate transformations may change bytes. It rejects observed links, reparse points and hardlinked files along inspected paths, and bounds fixture enumeration; these checks are not race-resistant and do not make it safe for hostile inputs. Use only trusted, owned test inputs. It does not model arbitrary Godot feature tags, PCK mapping, delay-import resolution, dynamic loads, or the Windows loader; a package-root absence is not proof of runtime failure. Exit 3 means unresolved checks remain with no non-advisory fixture finding, 1 means a non-advisory fixture finding, and 2 means invalid or incomplete input. The separate probe returns 0 for a parsed PE and 2 for invalid input; unsupported delay-import address forms are rejected.

Build with .NET 8 without an apphost and with package sources disabled if offline. For example, create a temporary `NuGet.Config` containing `<configuration><packageSources><clear /></packageSources></configuration>`, then run `dotnet build PeProbe.csproj --configfile <config> -p:NuGetAudit=false -p:BaseIntermediateOutputPath=<temp-obj>/ --output <temp-bin>`. No external NuGet packages are required by this project. The project does not include the Godot editor, header, export templates, Dependencies, generated DLLs or test exports.

`safe_open/` is an experimental Windows handle probe. It can hash and inspect one PE through the same opened stream; the fixture scanner accepts its DLL as an optional fourth argument. Build its project the same way with a distinct intermediate/output directory, then run `python safe_open/test_safe_open.py <SafeOpenProbe.dll> <experiment-root>` on disposable local fixtures. Pass the same DLL as the optional third argument to `test_fixture_spike.py` to compare scanner modes. The scanner still opens descriptor and source metadata separately and reopens the package root for each file; this optional mode does not close those races. See the portfolio result `secure-input-design-2026-11-18.md` for tested behavior and substantial limits; do not treat the experiment as hostile-input protection.

With the actual fixture exports prepared using `../fixture/build_owned.py` as described in `../fixture/README.md`, run `python fixture_spike.py <temp-bin>/PeProbe.dll <source-project>/addons/fixture/fixture.gdextension <export-dir>`. The companion tests take the probe DLL and the generated experiment root: `python test_probe.py <PeProbe.dll> <experiment-root>` and `python test_fixture_spike.py <PeProbe.dll> <experiment-root>`. These tests use generated external fixture files; those variants must be prepared before the tests will run.
